# Implementation contracts

[The vision](../vision.md) defines product scope. This document records the shared behavior that UI, CLI, persistence and tests must preserve. Supported features and current limitations belong in the root README; test-run histories stay local.

## Architecture and trust

Electron main owns application operations, persistence, files/Git, native provider controllers, PTYs and browser lifecycle. The renderer calls a typed, narrow bridge. `codctl` uses the same operations over a user-local socket; it has no separate business rules. The command catalog supplies CLI help and capability discovery. Agent integration uses the same CLI, without a separate Cod MCP server. `codctl context` resolves COD_CONVERSATION_ID (or explicit --conversation ID) to the current owning workspace and conversation metadata, excluding transcript and private drafts. It never falls back to the focused workspace.

External websites never receive Node.js or privileged Cod APIs. Markdown previews and registered agent pages have separate restricted protocols. The registered page bridge validates its server-bound origin, frame and payload; a page cannot choose another conversation. Downloaded files never execute automatically.

Use provider-native protocols and session identity, not a replacement agent loop. Capabilities must distinguish unsupported controls, missing installation, missing authentication and actual failure. At most one controller owns a native conversation. Opening, inspecting or discovering an existing session does not send a prompt.

Provider inspection is read-only and reports native capabilities rather than inventing equivalent controls. Standalone session commands such as `/skills` open inspection instead of becoming prompts. A selected skill carries its exact native name and path; ambiguous names require selection instead of dispatching several skills.

## Identity, layout and focus

A fresh profile exposes one Untitled workspace with an empty composer before either the GUI or command socket can observe it. Startup initialization must not race later workspace creation or capture focus after the user opens a command or starts typing. A profile with deliberately closed workspaces remains empty. Transient body focus during dialog teardown must not replace the remembered control, caret or selection.

- A workspace owns folders, conversations, saved material and a split tree. A pane group holds tabs; a tab refers to content. Moving or splitting a tab must not create another native controller.
- New chat remains available with no open workspaces: create a fresh unnamed workspace and empty composer without restoring closed tasks or starting inference. Reuse a pristine empty composer for this global action.
- New workspaces begin with a chat. Material opens to the left and chats/terminals to the right by default; explicit moves allow mixed tab types and nested horizontal/vertical splits.
- Both side toggles remain discoverable when only one pane exists. Revealing the absent side creates an empty view, not a native conversation; opening content replaces that placeholder. At least one group stays visible.
- Hiding and maximizing change visibility, preserving tabs and saved ratios. A maximized pane fills the working area below the title bar and temporarily hides both navigation panels and their resize handles without changing their settings. Restore returns the previous arrangement. Explicitly revealing navigation exits maximized mode. Navigation widths persist and clamp to the current window without overwriting the preferred width.
- Every operation accepts an explicit stable target. Commands exposes the same conversation/workspace management actions and guards as context menus, including rename, move, removal and native CLI handoff. The palette retains its original object IDs while open, refreshes action availability on state changes and preserves the query and valid keyboard selection. Agent-origin creation defaults to background. Status updates, slow navigation and streaming must not steal workspace selection, pane focus, caret or scroll.
- Explicit navigation may focus its content. Dismissing a picker restores the preceding focus and selection. Streaming follows the end only when the reader was already there.
- Successful CLI requests mean accepted operations, not finished inference. Errors leave state unchanged or expose a recoverable partial outcome; never silently discard drafts.

`conversation.move` relocates the existing conversation and its origin-bound reviews without closing its controller or restarting an active turn. Composer text, images and selected skills follow; unrelated tabs stay put. A pristine destination chat placeholder is removed, while populated drafts remain. The focused conversation follows by default; background transfers preserve unrelated focus unless explicitly requested. Native cwd does not change: returned state and inspection retain the actual directory, and agents must use explicit destination paths or tool cwd. Session-bound context resolves current membership on every call rather than trusting startup workspace environment variables. Review sources retain their original authorized roots across relocation.

The workspace tree separates keyboard focus from activation: arrows move focus, Space opens the focused workspace or conversation, and Enter starts inline rename. Enter saves and Escape cancels without starting inference or changing workspace membership. Renaming from a tab or Commands reveals the navigation panel and expands the target workspace. Keyboard completion or cancellation returns focus to the renamed row; saving on blur preserves the newly focused control. A conversation name is a persistent Cod display label and does not rewrite native history or message content. Review rows open with Space or Enter and never start rename. Their visual and accessible selection follows the active review pane; an expanded workspace parent is not selected at the same time as its visible child. Closing a workspace from navigation returns focus to the next surviving row, then the previous row, or the workspace switcher when no workspace remains. File-tree and picker activation retain their own Enter behavior.

### Workspace browser rows and new tabs

The workspace tree also lists its open browser tabs, including local reports, with the current page title and URL as fallback. Browser rows follow conversation rows and retain browser identity through loading, title changes, group moves and restart. Arrows move keyboard focus through tree rows without opening them; click, Space or Enter opens a browser row and reveals its workspace and pane. Browser rows expose Close tab and Reload in the context menu, with Delete closing the focused row and returning focus to a surviving neighbor. Closing removes the row; Reopen closed tab restores the browser and its navigation. Page titles remain owned by the website: browser rows do not rename on Enter. Collapsed workspace counts include conversations and browsers. Focusing the workspace panel uses its retained row, otherwise its active visible child, including a browser tab. A focus command arriving between an accepted workspace change and its batched tree render waits for that render rather than retaining a row from the previous workspace. Its return target falls back to the current workspace content when the remembered control belongs to an inactive workspace. Browser rows do not add notification status or custom names.

Within an open workspace, the pane's plus button and New tab command (default Cmd/Ctrl+T, editable through the existing keymap) immediately create and select a blank tab in that exact pane. Its content offers Open file, Browser, Chat and Terminal using shared controls; Tab/arrows and Enter/Space operate the choices. No modal precedes it. Explicit New chat, New browser tab, New terminal and Open file commands retain their direct entry. The selected choice carries the blank tab identity through asynchronous creation or file search. If that tab has closed or changed, fail explicitly rather than opening in another tab. Selecting a type replaces the blank tab in place, keeping its pane and position; it does not create an extra split or leave a redundant placeholder. Cancelling file search returns to the unchanged blank tab and choice. Blank tabs can be moved, closed, reopened and restored after restart without creating a native process. Closing the blank tab returns to a surviving tab. There is no separate default-type preference: the general action always offers the four choices and direct actions remain independently bindable. New workspace still starts with chat.

Tab dragging selects an insertion position rather than always appending. Following [Zed's tab drop handling](https://github.com/zed-industries/zed/blob/main/crates/workspace/src/pane.rs), show a narrow insertion marker, keep the dragged tab's identity, and commit one indexed move on drop. The comparison is based on upstream source inspection, not a live Zed GUI run. Dropping on the same slot is a no-op; Escape or dropping outside a Cod tab bar preserves order. Moving across pane groups retains drafts, controller identity and the destination position. Overflowing tab bars scroll while dragging near their edges. Background updates must not replace the drag source or move close targets. The moved tab remains selected; keyboard focus returns to its tab when the drag began there. Existing Move tab left/right and Move to pane actions remain the keyboard alternatives, and order survives restart. Cross-workspace dragging, window tear-off, modifier-drag duplication and drag-to-split are intentionally outside this slice; existing explicit split actions remain available. No drag-specific configuration is introduced.

### Icon control geometry

Regular and compact icon buttons use the shared component and size tokens. Their painted hover, pressed and keyboard-focus area is square; the global text-button minimum height must not stretch a compact icon button. Tab Close and pinned Unpin use the compact variant, with the same geometry for short, long and clipped titles. Interface font changes apply live through the existing shared settings; display scaling changes physical pixels without changing the square shape. Disabled icons retain their geometry, do not brighten on hover and cannot activate. Tab-bar New tab and Maximize use the regular variant. Tab Delete / Close tab keeps its current behavior; Enter/Space on a focused icon button performs that button's action, without activating its surrounding tab. No new preference, rename flow, dialog or persistence state is introduced by this geometry repair.

Delayed pane selection remains keyboard usable. A native page can hide either side and the configured positional focus commands can restore the chosen side; once its state and DOM are delivered, the selected chat receives actual composer focus and immediate typing extends its existing draft. Focus completion must follow rendered state, not an assumed animation-frame count or the operation reply alone. A newer explicit navigation, modal, closure or workspace change cancels an obsolete completion, and no old native notification may restore a hidden side. Mouse activation and focus-return commands retain the same target and cancellation rules. Delayed menu close cleanup restores its origin only while focus still belongs to that menu or the page body; it must preserve a newer composer, file or navigation focus. Drafts, native page identity and restart layout remain unchanged; this repair introduces no user setting or new shortcut.

### Manual Developer Tools

F12 and Commands > Toggle Developer Tools toggle the inspector for the invocation's focused surface. Chat, files, navigation and browser chrome belong to the Cod renderer; native website and registered-page content use their own WebContents. Commands retains the native origin when opened from a page, even though the palette itself belongs to Cod. A vanished target fails rather than falling back to another page or the app. Inspection never changes workspace, tab selection, resource identity or drafts.

The alternate shortcut follows [Electron's native menu source](https://github.com/electron/electron/blob/main/lib/browser/api/menu-item-roles.ts): Command+Option+I on macOS and Ctrl+Shift+I on Linux. Bindings come from the shared registry; keymap overrides are validated, apply live, survive restart and reset to these defaults. Bare function keys are allowed in explicit keymap configuration without admitting unmodified text keys. Terminal editing authority is preserved for remapped control-letter shortcuts. Electron's internal inspector window does not deliver `before-input-event` ([upstream limitation](https://github.com/electron/electron/issues/28770)); it uses native Close, while toggle shortcuts act from the inspected surface. Cod intentionally does not add a custom inspector window or global keyboard hook to override this. This comparison is based on source and [Electron WebContents documentation](https://www.electronjs.org/docs/latest/api/web-contents), not an observed Zed GUI.

Inspectors open as ordinary detached Electron DevTools windows, identify their inspected page and can be closed through their native controls or the toggle shortcut from the inspected surface without closing the page. Ordinary browser context menus expose Inspect element at the clicked coordinates; registered pages with their restricted response bridge intentionally omit that action. Escape/cancel retains the context-menu origin. Existing rename and selection behavior is unchanged. Closing the owner destroys its inspector; reopening a tab or restarting Cod does not automatically open tools. No inspector-open preference is persisted, no runtime agent CLI capability or debugging port is added, and renderer/browser sandbox and bridge isolation remain intact.

## Persistence and lifecycle

Persist layout, resource IDs, open views, composer text/images/provider/selected skills, native-session references, file drafts, review drafts and close/reopen history. Restore records without replaying commands, inference or arbitrary website form submissions.

Composer typing persists the latest text without echoing the application snapshot back to its originating UI. Consecutive trusted text edits may share a durable save within a 150 ms batch; intervening operations form ordering barriers, so a delayed save cannot restore a sent or cleared draft. Save acknowledgment still follows durable persistence, and failures reject all callers in the batch. Text-only edits atomically save a small `composer-text.json` overlay without cloning or serializing histories and attachments. Full state checkpoints include the latest drafts and advance an internal checkpoint token; startup applies an overlay only to its matching checkpoint, so stale text cannot resurrect a sent or cleared draft. Corrupt matching draft storage prevents silent recovery with lost text. Text-only `conversation.composer` updates preserve existing images when `images` is omitted; an explicit empty array removes them. Attachment changes and CLI composer updates still notify the UI.

Pasted images insert stable `[Image N]` references at the current selection. Attachment removal removes its insertion marker without renumbering other images; thumbnail captions and provider content identify the same image. References and image data persist with composer drafts. Sending waits for attachment reading to finish.

Composer ownership follows the conversation identity, not a reusable pane. After a failed create or resume, opening another conversation in the same pane must bind typing, attachment and send actions to the new conversation. Its unsent text and images must survive switching chats and restarting the app.

Streaming updates may be batched for display; user actions still publish immediately. Collapsed tool rows retain their summaries without constructing full output blocks until expanded, and closing a row releases its rendered output. Background streaming must not require renderer copies or full JSON comparisons of all conversations merely to detect a focus change.

Browser restoration loads an ordinary page only when its actual visible viewport is laid out or navigation is explicitly requested. Inspecting records and changing unrelated state do not wake dormant pages. Already loaded views remain alive across workspace switches, preserving forms and media. Failed-page diagnostics may create a passive error view without retrying its URL. Native view destruction during application shutdown must preserve saved tab records, including when shutdown begins while a close decision is pending.

Browser tab close honors the page's native beforeunload prevention before removing its pane or adding reopen history. Stay is the default and preserves the existing page and form; only Leave discards it. CLI closure uses the same behavior. Workspace close asks guarded pages before stopping agents or shells. If a later page cancels, earlier explicitly discarded tabs remain individually reopenable and the workspace stays open; no cancelled tab is archived as closed. This protection applies to tab/workspace operations, not forced process termination.

Closing and immediately reopening a tab leaves the restored tab selected and ready for typing. A late physical-focus completion from the close cannot issue another selection and switch back to its fallback tab. Closing a chat tab removes the view, not its conversation or active turn. Closing a terminal stops its owned shell; reopening requires an explicit fresh-shell action. Closing a busy workspace identifies the work that will stop and defaults to Cancel; CLI callers must explicitly request forced closure. Failed stop or mutation retains usable context. Externally owned CLI sessions are not silently seized or killed.

Sending a chat message during an active turn durably appends it to that conversation's FIFO queue instead of rejecting it. Text, image references/data and exact skill references stay together. The same queue operations serve UI and CLI. Waiting entries appear above the composer and can be cancelled or edited in place without replacing the next draft; an entry being edited blocks dispatch until saved or cancelled. Successful native completion starts the next entry without stealing focus. Interruption, provider failure and application restart pause the queue until explicit continuation. A persisted in-flight entry becomes uncertain after restart and must never be resent automatically; show its uncertainty and allow dismissing it after native-history inspection. Removing a conversation or handing it to the native CLI requires resolving its queue first. Closing only the chat tab preserves the queue and running work.

An attached Codex controller also accepts native turns started externally (for example by `codex queue`). Their input, streamed replies, tools, permissions, interruption and completion attention use the same conversation path as a composer send, without stealing focus or creating another session. Stale or unrelated turn events cannot restart completed work. Cod does not synthesize completion messages for background commands; a skill or script must enqueue them.

Native handoff refuses an active or initializing controller, queued messages, pending permissions, an unresolved origin-bound review or an unfinished interactive page before releasing any controller or starting a terminal. The same reason disables Continue in CLI in context menus and Commands; another conversation's pending feedback does not block the target. Closing the interactive page or resolving the review makes handoff available again. Native handoff releases Cod's controller before starting the provider CLI. Reclaim checks ownership and resumes the same identity/history without an implicit prompt. Transaction rollback must not resurrect stale process, completion or terminal state.

Command names, shortcuts and surface scopes come from one shared registry used by the renderer and native views. A physical key dispatches once; repeated destructive commands are consumed without repetition. IME and AltGraph input stay with the focused control. Non-Latin letter layouts use physical key fallback while Latin layouts retain logical shortcuts. Websites keep their editing and printing keys, and terminals retain shell control keys; the command palette still reaches Cod navigation. Current-content find uses the active surface, including native page search; its shortcut is scoped to avoid stealing terminal readline keys. Focus-and-return commands reveal an existing chat or terminal in the current workspace (creating an empty chat or shell only when absent), and restore the prior control and caret on a second press. Left/right pane visibility and focus depend on layout position, never tab content. A sole pane occupies the left position; revealing the absent right position creates an empty pane without a conversation or inference. Toggle preserves tabs and ratios and cannot hide the last visible pane. Focusing a hidden side reveals it and focuses its active tab. Product defaults follow platform/editor conventions without function-key navigation defaults or system task-switching collisions. Personal layouts are optional configuration, not product defaults. The effective registry incorporates validated `keymap.json` overrides from the data directory; reload is atomic, invalid configuration uses defaults, and hints/reference/native handlers share the effective bindings. Restoring focus to a native page must restore actual input focus, not only active styling. A pane-hide shortcut received by a native browser page leaves the pane hidden and transfers real typing focus to the surviving content; a transient focus return to an older editor cannot reopen the hidden pane.

Use shared desktop field, menu, tree and tab conventions. Collapse historical tool activity per turn without hiding pending approvals or actionable failures. For providers without explicit final-message phases, keep the last assistant text visible after completion even if tool updates follow it. A saved completed turn with no assistant text shows a missing-reply notice. Kimi's native ACP can report end_turn for an internal failure without exposing its reason; a completion containing neither assistant text nor tools is an error rather than proof of a successful answer. Do not infer a specific quota/authentication cause from an empty response.

## Pinned tabs

Pinning protects any tab kind, including chats, browsers and an unfilled New tab, from routine closure. Pin state belongs to the stable tab identity, not its title, resource type or numeric position. Each pane places pinned tabs first, retaining order inside the pinned and ordinary segments. Pinning or unpinning moves the tab to the segment boundary without activating a background tab or disturbing its content, draft, native session or running work.

Mouse entry uses Pin tab / Unpin tab in the tab context menu; pinned tabs replace their close button with an unpin icon. Commands exposes Toggle pin tab, Close other tabs and Close all tabs, with the existing validated keymap file owning optional bindings and its reset/live reload behavior. There is no new default pin shortcut: Zed uses a chord, which Cod's single-stroke registry does not support; inventing a conflicting shortcut is intentionally avoided. Keyboard tab navigation and native-page Commands target the same exact tab as mouse actions. Escape cancels menus and returns focus. Pin actions neither rename tabs nor change existing inline rename/cancel behavior.

The ordinary Close tab command/shortcut, tab Delete and middle-click never close a pinned tab. For Close tab on a pinned active tab, activate the first ordinary tab in that pane, otherwise an ordinary tab in another visible pane; if none exists, leave focus unchanged. Do not close that newly activated tab in the same invocation. An explicit Close tab context-menu action can close a pinned tab, subject to the existing unsaved-page guards, and Reopen closed tab restores its pin and original pane/position when that pane still exists. Bulk Close other/all/left/right tabs excludes pinned tabs and stops on a cancelled browser close. Their target pane and anchor remain stable during asynchronous close decisions. CLI operations share these protections; explicit inclusion of a pin is opt-in, not inferred from a resource ID. Removing a pinned conversation from a workspace requires unpinning it first; closing its view never removes its conversation or active turn.

Reordering and moving, including split and cross-workspace chat moves, retain pin state. Drops and keyboard reorders clamp to the matching segment; the insertion marker shows the final destination. Ordinary new tabs stay after pins. An explicit whole-workspace close may archive pinned tabs along with the workspace; reopening restores pins and order. Restart retains pins, selection, drafts and provider identity. A pinned blank tab keeps its pin when its File / Browser / Chat / Terminal choice replaces its content. A pinned pristine chat placeholder is retained during incoming chat moves and is not reused by the global New chat action. Pins do not start background work or load dormant browser pages. A page that destroys its own native view retains a pinned recovery tab; reopening the page is explicit and cannot restore lost in-page state.

Reference: inspection of upstream [Zed pane source](https://github.com/zed-industries/zed/blob/main/crates/workspace/src/pane.rs) and [default macOS keymap](https://github.com/zed-industries/zed/blob/main/assets/keymaps/default-macos.json), not a live Zed GUI session. Zed places pins first, substitutes an unpin icon, protects normal close/bulk close and permits explicit context close. Cod deliberately retains pins across drag boundaries rather than implicitly unpinning on a drop, because the task is protection against accidental loss. A separate pinned row, icon-only browser pins, default multi-stroke chords and protection against forced process termination are intentional omissions. No new appearance/protection setting is needed: pin/unpin is the per-tab choice and keymap overrides are the shared configuration authority.

## Attention and plugin ownership

The provider plugin owns task-status policy. Cod owns technical connection state, status storage, CLI reporting and presentation. A failed process or pending permission cannot be hidden by a stale plugin-ready report. Pending review remains visible until submitted, and hook lifecycle reports cannot overwrite explicit review status.

Technical `ready` means idle; it is not itself a new notification. A successful native completion advances a revision. Explicit chat activation or acknowledgment marks that revision read; a later completion becomes visible again. Options discovery, resume and cancelled turns do not create new completion attention. Completion and acknowledgment revisions persist through restart. Workspace and child rows use the same status meaning and marker.

Plugin installation previews an explicit provider profile, preserves unrelated configuration, backs up modifications and rejects edited managed files or changed preview inputs. It never bypasses native trust, changes authentication or installs silently at startup.

## Files and repositories

File browsing, filename quick-open and content search are separate interactions. Results include repository/path/line identity. Multiple repositories may contain the same relative filename; status, changed lines and diffs must use the correct repository. Branch comparisons compare the two explicitly requested trees, without an implicit merge base.

All views of a file share its current draft. Visible source editors check a small file-version token periodically and on focus. External changes reload clean buffers; dirty buffers retain their text and expose an explicit, confirmed reload from disk. Returning responses must not replace a newer saved revision. Saving during newer input must not lose that input. External changes, deletion, rename, symlinks and collisions preserve the unsaved version and offer explicit recovery rather than silently replacing data. Tree refresh must find externally created and committed files even when Git is clean, without losing focus.

Composer updates from the CLI reach already-open drafts, including text, images, skills and provider choice. A renderer serializes its saves and checks the saved draft version before replacing it. An external update never silently overwrites unsaved local edits: retain both versions durably and offer Keep my message or Use saved version at the composer. Further typing updates the local recovery draft; later external writes update the external version. Both variants and their attachments survive restart until explicit resolution. Sending is blocked while a conflict is unresolved. A single writer must not conflict with its own send or queue admission when state notifications are delayed: clearing a submitted message retains one empty version transition for its writer, allowing that writer's already-started autosave to rebase without overwriting a later external version. Further typing and newly attached images remain independently durable while admission is pending. Successful admission removes only the images included in that submitted message; failure retains them alongside any newer attachments. The transition carries no message text or attachments and is replaced by the next ordinary save. Failed admission retains the unsent message, attachment references and caret. Actual concurrent changes still preserve both versions through switching, restart and explicit resolution. Conflict copy describes two versions of an unsent message without asserting that another window was involved. This keeps the familiar chat send-and-continue task; no additional user preference or conflict dialog is introduced. Text-only saves keep using the small composer overlay and exclude both variants' image data from it.

## Reviews and registered responses

Document review uses a read-only source editor with syntax highlighting, a caret and native text selection. Source editors render files above 200,000 characters as native plain text without the highlighting overlay, preserving visible text and editing for large single-line files. Markdown also has a formatted view with highlighted code and Mermaid, sharing the normal preview renderer. An eye button exposes preview on Markdown tabs and reviews; Toggle Markdown preview is available in Commands. Ordinary preview opens beside the editable source and reuses an existing preview for the same file, without saving or discarding file drafts. Review switches view within the immutable snapshot.

Document comments appear at their anchor: after the corresponding Markdown block in preview, beside the source line in the source editor, and after the selected diff line. Saving, editing or deleting a comment must retain the document instance, caret and viewport while its snapshot is unchanged. The review toolbar sits directly below the tab strip.

Document comments can anchor exact text fragments, not just whole lines. Source anchors use UTF-16 offsets in the snapshot; formatted anchors use offsets in the shared rendered text projection and retain the corresponding source block lines. The service validates the range and derives the saved quote itself. Quotes and offsets survive restart, delivery and view changes; refresh retains outdated anchors rather than guessing a new location. Diagram comments select the Mermaid source. Existing line-based document and diff anchors remain supported.

A review binds its source, repository and originating conversation. The user can comment or edit while discussing the document alongside it. Comments remain private until one explicit round submission; an empty round may submit an approval. There is no recipient selector or fallback destination.

Freeze submitted text, anchors, source revision and destination. Sent rounds are immutable. Changed or ambiguous anchors become outdated and require explicit reattachment; refreshing a review never silently attaches feedback to unrelated text. Show changes between review revisions. Persist unfinished comment editors and saved comments separately from delivery.

Delivery distinguishes private, queued, sending, acknowledged and uncertain states. A stable packet identity prevents duplicate delivery. An interrupted dispatch must reconcile native history before retry; an immediate send return is not a remote receipt. `review wait` completes on durable submission, not on completion of the agent's next turn. A waiter may reconnect using the review ID.

Registered HTML reports can follow links to files within their registered directory and return with native Back/Forward. JSON, JSONL, text and image evidence must render rather than leave a blank page. Native page context menus expose navigation, selection and clipboard actions. Following a link does not grant the destination the registered form submission bridge; only the exact registered entry has that capability. Ownership, directory boundaries and symlink escape checks still apply.

A registered form response has the same origin and durable admission protection. Reserve the submission before dispatch, reject duplicates, and restore interrupted sending as uncertain. Keep submitted or uncertain forms read-only. A definitely unsent failure remains explainable and retryable; never silently send to another conversation.

## Browser and terminals

Address entry accepts HTTP/HTTPS URLs, local `file://` URLs, bare hostnames and search text. Local HTML references in chat and Markdown open in ordinary browser tabs with address, Back/Forward, Reload and the same recovery and restart history as websites. Relative links and assets resolve against the actual file location, including sibling and parent directories. Explicit file opening and the file tree retain source editing; a reference with a line number targets the editor. PNG, JPEG, GIF and WebP files open in a Cod document preview through file opening, chat references and the file tree; reopening the same image reuses its tab. The preview supports fit-to-pane, actual size, zoom and scrolling without browser chrome. Explicit absolute file references and `~/` paths may point outside workspace folders; relative references stay within those folders. Automatic inline image loading remains restricted to workspace folders. Image data is bounded to 20 MiB, loaded only for an opened preview and released when its tab closes. Binary data is never decoded with replacement characters into an editable document or written back through text save. Local pages stay sandboxed without Node.js or Cod APIs; websites cannot navigate themselves or open popups into local files. Remote file shares are unsupported. Forms explicitly opened with `page.open` retain their separate origin-bound response permission. Bare public hosts use HTTPS; localhost and loopback hosts use HTTP. Ordinary text uses the configured search engine (Google by default, with DuckDuckGo, Bing and Yandex available); explicit unsupported URL schemes fail without navigation. Opening an exact URL through `browser.open` remains strict, while `browser.navigate` uses the same address resolution as the UI. Empty tabs show a blank address field and a grid of pinned sites without recents or section headings. Pins are shared across workspaces, editable in place and persisted in the application profile; pinning an existing URL updates its name without adding a duplicate. Current-page pinning is available through Commands, and pin/unpin operations are available through the CLI.

Web links have explicit Open in system browser actions in conversation/Markdown link menus, source-editor caret/selection link actions and Commands for the current browser page. Ordinary activation keeps using Cod's existing managed navigation; this change does not introduce global URL deduplication. Mouse context menus and Shift+F10/Context Menu use the shared menu behavior: arrows choose, Enter activates once, Escape cancels and restores the previous control/selection without changing a draft. Markdown preview messages are accepted only from the matching registered preview frame. Source link extraction inspects the selection/current line rather than indexing a document or transcript. Open link and Open in system browser are discoverable commands with optional shared keymap overrides, no new default chord, toolbar button or separate preference. Rename is unrelated to these ephemeral actions.

System-browser handoff accepts explicit validated HTTP/HTTPS URLs only and uses Electron's platform handoff once, without adding a Cod tab or persisting a launch. If Cod is itself the default handler for that scheme, reject with a useful error rather than routing the link back into Cod. Choosing an alternative browser application, non-web schemes and importing profile data are intentional omissions. Operation errors do not replace the source document/page. No external handoff is replayed after restart.

Ordinary native-page link menus additionally offer Open link in new tab. It always creates an independent background managed tab beside the source in its original group/workspace, even if that URL is already open, retaining source focus, form contents and shared login profile. The contextual destination has no opener or response bridge; existing Chromium window.open/form-POST handling retains its native opener behavior. HTTP/HTTPS and safe local-file links from local-file pages are supported; remote-to-file, privileged extension/registered-artifact URLs and unsupported schemes are not widened. Registered form pages offer these actions only for ordinary web links. Native Back/Forward/Reload, editing/selection actions, Copy link address, select controls and cursors remain Chromium-owned. Closing an owner closes its menu safely; reopening/restarting restores managed tabs, not menus or pending handoffs.

Reference comparison is from [Electron context-menu documentation](https://www.electronjs.org/docs/latest/tutorial/context-menu), [WebContents](https://www.electronjs.org/docs/latest/api/web-contents) and [Chromium context-menu source](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/chrome/browser/renderer_context_menu/render_view_context_menu.cc), not an observed GUI. Chromium's background-tab convention is retained. Context tabs intentionally use the existing host-owned browser admission rather than injecting window.open into an untrusted page, so they do not acquire an opener or a referrer from that page. Verification records the platform handoff boundary in isolated Linux rather than claiming live OS-browser GUI compatibility.

Browsing history stores up to 2000 distinct successful HTTP/HTTPS destinations in a private local file, queried on demand rather than included in chat state snapshots. Local address suggestions combine pinned sites, bookmarks and history, preserve typed text until explicitly selected, support arrows/Enter/Escape and never make network requests while typing. Authentication callback URLs and URLs containing credentials or authentication tokens are excluded. History supports search, individual removal and clearing across restarts. Optional bookmarks are independently persisted, searchable and editable in place through their manager and CLI. Bookmark commands do not add persistent toolbar controls, change home pins or depend on history retention.

Address focus is quiet: clicking/selecting a loaded URL or using the address shortcut from native content does not request or display suggestions. Typing a value different from the committed destination requests local suggestions after the existing debounce; restoring that destination cancels them. Empty home focus also stays quiet because pins already appear on the home grid. Arrow Down explicitly opens local alternatives, using the empty local query when the address is unchanged, and selects the first result. Arrow Up/Down then cycle results without replacing the typed text; Enter activates only an explicitly selected result. The current committed URL is excluded from the dropdown, while CLI suggestion queries retain their existing result/ranking contract. Escape dismisses suggestions and retains address focus and typed text; blur dismisses them without navigation. Copy/select-all never requests suggestions. Composition does not query until its committed input. Dismissed, superseded or composition-time async replies cannot reopen the list. New navigation and restart use the latest committed destination for this comparison.

This quiet-focus choice intentionally differs from Chromium's optional [on-focus zero-prefix suggestions](https://chromium.googlesource.com/chromium/src/+/main/components/omnibox/common/omnibox_features.cc); [Firefox's documented local suggestion sources](https://support.mozilla.org/en-US/kb/firefox-suggest) inform the as-you-type flow. This is a source/documentation comparison, not an observed browser GUI. No new setting, persistence model, rename action or network lookup is introduced; existing browser settings, search resolution and shared keymap remain in force.

Browser tabs retain independent history/address state and share one persistent profile. Closing/reopening and application restart preserve up to 50 safe URL/title navigation entries around the active position, bounded to 64 KiB per tab, with native Back/Forward restored when the tab is loaded. Initial empty entries are omitted when a real page is active. Persisted navigation excludes Chromium pageState, form values and POST payloads; restoring a page requests its URL without resubmitting a form. Inactive restored tabs remain dormant. Failed-page restoration remains passive, with its saved navigation available only through explicit recovery. Site blocking preferences and downloads survive tab closure. Native foreground/background tab requests open managed tabs in the originating workspace and tab group without replacing existing work. Background workspace or tab requests preserve the current focus. Native opener relationships and form POST submissions survive this routing; closing an opener leaves its managed tabs alive. Explicit native window requests remain sandboxed popups, and page self-close removes the corresponding managed tab. Authentication retains its required opener relationship. A failed navigation keeps its last successfully committed web page available through an explicit recovery action. Reload retries the failed address; reopening or restarting a failed tab restores its error state without automatically requesting the failed address again. Native browser/agent-page focus must route close, address and command shortcuts to the correct view.

Downloads belong to the shared browser profile, survive tab closure and expose progress, pause/resume/cancel, explicit retry, open/reveal and history removal through UI and CLI. Filename collisions never overwrite existing files. Restart restores history without automatically retrying requests; removing history never deletes files. A toolbar entry appears only when download history exists.

Site permission decisions are keyed by requesting origin, embedding origin and permission. Requests stay with their browser tab and never steal focus. Allow once lasts until navigation; remembered allow/block decisions survive restart and can be reset to Ask. Pending requests expire and are rejected on navigation, tab closure or shutdown; stale answers cannot grant a replacement page access. Camera and microphone are separate permissions. Changing a saved policy affects future requests; the UI offers guidance to reload an active page. Unsupported permissions stay denied.

Host the real Bitwarden UI. Cod owns placement, active-tab binding and load/retry errors; the extension owns vault interaction. Never infer successful autofill from popup loading. Filter cache identity includes lists and resources; failed updates can retain a verified cache only with an honest visible state.

Terminals are real PTYs with explicit cwd, byte-preserving input and resize. Hiding keeps them running while Cod is open. Ended shells retain useful output/context, but no restart action replays their former command.

## Acceptance boundaries

Navigation responsiveness is measured from the actual keyboard or mouse action to its first visible result and settled frame, separately from native page navigation and paint. Compare an empty profile with representative saved histories, attachments, multiple workspaces and already loaded native pages, both idle and while another conversation streams. Account separately for renderer work, IPC and operation queueing, persistence, state snapshots and native creation/layout/focus. A navigation action must not perform unnecessary work on unrelated history, lose draft text or weaken durable close/reopen and restart behavior. Correctness and responsiveness evidence are separate; a final selected tab does not establish that switching was fast. No animation, framework replacement or new preference is implied by this repair. JSON-line readers inspect each incoming chunk once and join a completed frame once, retaining their existing size, timeout and UTF-8 limits. Provider diagnostics that do not change application state must not trigger state broadcasts or disk writes. Renderer snapshots include complete transcripts only for the visible chat tabs; hidden chats retain their label, queue and attention metadata without copying historical tool output or image bytes. The CLI and durable history remain complete, and switching a chat into view supplies its current transcript. Rollback backups do not clone live provider fields that rollback already preserves. Native browser metadata changes share the existing short snapshot batch, while initial tab creation remains visible independently of page loading.

Long conversations initially render a recent text-bounded window rather than synchronously formatting every historical message. Scrolling to its beginning loads an earlier window without moving the current content; an Earlier messages action also provides keyboard access. Current-content search includes the full history, and full-history search can still require substantial rendering for a very large conversation. Navigation and new messages retain the composer text, selection, attachments and the latest answer; loading older content never truncates persisted or CLI history. This repair introduces no additional storage format or transport protocol.

Exercise complete journeys with real Electron, temporary files, real Git and real PTYs: create/switch tasks, discuss/edit/review a spec, implement across two repositories, interrupt work, return later, close/reopen and restart. Include mouse and keyboard paths, native embedded-view shortcuts, concurrent changes, failures and recovery. Inspect screenshots at normal and wide window sizes; passing assertions alone does not establish coherent design.

Scripted provider subprocesses verify deterministic protocol and UI behavior. Separately verify live identity/history round trips, permissions, interruption, images and plugin execution for each supported provider. Credential or platform gaps are BLOCKED, not inferred passes.

Official-extension checks must exercise login/unlock, generation, saving, actual content-script autofill and restart against an invented vault. Ad-blocking fixtures verify network/cosmetic integration and host exceptions; representative public-site comparisons are needed to claim AdGuard-comparable effectiveness. Keep real account data, screenshots, logs and per-run evidence in ignored local artifacts.

Diff reviews render the saved unified diff in hunk order: context appears once with both line numbers, additions and removals retain their own side, and missing-final-newline markers remain visible. Existing snapshots use their saved diff text and manifest without migration. Comment selections must stay within one file, hunk and side; context supports either side so old-side anchors remain valid.

## User settings

Global settings use a validated flat-key `settings.json` in the profile. GUI and CLI updates share the same service, serialize mutations and atomically persist before acknowledgment. External edits apply without restart; invalid JSON, unknown keys and invalid values retain the last valid configuration and prevent GUI writes over the broken file. Font families/sizes are separate for interface, source editor, chat and terminal. Cursor shape/blink and scrollback apply to open terminals. Workspace chat width overrides the global default. Keybindings retain their existing validated file and authority rules. Settings search, per-setting reset, global reset, JSON editing and shortcut discovery are available from Settings. Browser search engine selection participates in this search and reset while keeping its existing browser-library ownership. Global reset resets appearance and the search engine, preserving keybindings, pins, bookmarks and browsing history. If one store fails after the other was reset, report the partial result explicitly rather than claiming an atomic reset across both. UI transient layout and drafts remain separate from user configuration.

## Local diagnostics

Local runtime diagnostics correlate process memory samples with WebContents IDs and opaque browser-tab/workspace IDs. Include registered pages and browser popups. Keep the last known PID for renderer failure/responsiveness events and update attribution after navigation or process replacement. Multiple views may share a process; do not attribute the application's shared renderer to one workspace. Never record URLs, document paths, page titles, conversation text or workspace names for this attribution. Diagnostics remain bounded and local and must not prevent startup, navigation or shutdown.

## Workspace Overview

Overview is a transient second presentation of the sidebar navigation, sharing object identities, order, labels, attention precedence, pin state and targeted actions. It does not copy histories or attachments, persist its query, or maintain another application store. Sidebar visibility and its default stay unchanged.

The [Zed navigation documentation](https://zed.dev/docs/finding-navigating) informs the search-and-Enter picker behavior. Cod retains its workspace hierarchy instead of the recent-use ordering documented for Zed's tab switcher. This is a documentation comparison, not a live desktop observation.

- OV1: Commands, the workspace-title control and configurable Mod+Shift+O open one searchable overlay. Repeating the command cancels it. Existing workspace-panel focus bindings stay unchanged; keymap validation, reload/reset, shortcut discovery and native page dispatch use the shared registry.
- OV2: Empty search shows the workspace hierarchy, locally expanded through the active object. Up/Down highlight without activation; Enter or a row click opens the stable selected object. Text-caret Left/Right remain ordinary editing. Alt+Left/Right collapse/expand or select parent/first child. Disclosure/action controls never activate the row. Only the selected row's actions enter the Tab order.
- OV3: Case-insensitive tokens match workspace names, full conversation labels, browser title/URL and review labels. Matching descendants keep ancestor context; workspace-only matches include children. Search never indexes transcripts/page content or wakes dormant pages. Clearing the query restores unfiltered expansion/scroll. Long labels retain full accessible names and wrap within the wide responsive picker.
- OV4: Escape cancels in one press, as do outside click and the opening shortcut. Cancellation restores editor/chat selection or actual native browser focus; activation closes the overlay and focuses the destination after its accepted state renders. A newer explicit focus request wins over an older pending request. Hidden/maximized panels are unchanged by opening/cancellation; activation reveals its destination through existing operations.
- OV5: Right-click, Shift+F10 or the selected row's action control use shared actions/guards. Inline workspace/conversation rename saves with Enter, cancels with Escape and preserves query/selection; a locally renamed or moved item stays visible with its ancestors until the query is edited. Blur saves a valid label without stealing a new focus target. Browser rename/transfer are unsupported existing capabilities and are not synthesized by close/reopen.
- OV6: Pin/Unpin operates on the existing pane ID. Explicit Close tab retains native session membership and follows existing pinned/beforeunload contracts; Remove conversation and Close workspace retain existing queue/agent/review/form safeguards. Conversation move reuses the existing destination picker and preserves native identity/draft/reviews. Cancel returns to the same Overview context.
- OV7: Streaming/status/title changes and removals reconcile by ID without replacing the query input, resetting scroll or recency sorting. Removed selection falls to its next surviving neighbor, previous neighbor, then parent. Errors leave the overlay usable and visible. Restart restores existing application objects/pins/layout, never reopens Overview or replays an action.
- OV8: Verify keyboard and mouse paths from empty profiles, hidden/maximized layouts, duplicate long labels, a selected editor/chat draft, native page input and review. Verify background CLI mutations and restart. Measure input-to-visible-results separately with 50 workspaces/1000 rows and retained large histories/attachments, including background streaming: target p95 below100ms and no individual update above200ms on the isolated runner, with no accumulating DOM/handlers over20 open/close cycles. Report resource contention explicitly; final values alone are not latency evidence.

Intentional omissions: previews/thumbnails, MRU sorting, global content search, multi-selection, Overview drag/drop, sidebar removal/default changes and new browser lifecycle capabilities.
