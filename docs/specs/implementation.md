# Implementation contracts

[The vision](../vision.md) defines product scope. This document records the shared behavior that UI, CLI, persistence and tests must preserve. Supported features are summarized in the root README; detailed usage and current limitations belong in [the usage guide](../usage.md). Test-run histories stay local.

## Architecture and trust

Electron main owns application operations, persistence, files/Git, native provider controllers, PTYs and browser lifecycle. The renderer calls a typed, narrow bridge. `codctl` uses the same operations over a user-local socket; it has no separate business rules. The command catalog supplies CLI help and capability discovery. Agent integration uses the same CLI, without a separate Cod MCP server. `codctl context` resolves COD_CONVERSATION_ID (or explicit --conversation ID) to the current owning workspace and conversation metadata, excluding transcript and private drafts. It never falls back to the focused workspace.

External websites never receive Node.js or privileged Cod APIs. Markdown previews and registered agent pages have separate restricted protocols. The registered page bridge validates its server-bound origin, frame and payload; a page cannot choose another conversation. Downloaded files never execute automatically.

Use provider-native protocols and session identity, not a replacement agent loop. Capabilities must distinguish unsupported controls, missing installation, missing authentication and actual failure. At most one controller owns a native conversation. Opening, inspecting or discovering an existing session does not send a prompt.

Open existing native session opens a searchable picker for the selected provider and working directory. Opening or filtering the catalog never sends an inference prompt. The filter matches native title/preview, identity and cwd locally; Up/Down selects rows while text focus remains in the filter, Enter or a click opens the selected native identity, and Escape/Cancel restores the invoker and its text selection. No match, discovery failure and manual identity entry remain explicit. Provider/directory refreshes supersede old replies and errors; dismissed pickers cannot be repopulated by late responses. Opening an identity already attached to Cod focuses that existing conversation in its current workspace, preserving its cwd, membership, draft and controller instead of creating another controller. Only providers with a verified native integration are offered; authenticated compatibility remains separate from catalog filtering. The picker does not rename native sessions, convert history, scan arbitrary projects or introduce a search preference. Reference: documentation inspection of the [Agterm conversation-picker recipe](https://github.com/umputun/agterm/tree/master/cookbook/claude-conversation-picker) established directory-scoped selection and cancellation before resume, rather than a live Agterm GUI comparison. Cod keeps provider catalog labels and avoids the recipe's inference-based naming pass.

Provider inspection is read-only and reports native capabilities rather than inventing equivalent controls. Standalone session commands such as `/skills` open inspection instead of becoming prompts. A selected skill carries its exact native name and path; ambiguous names require selection instead of dispatching several skills.

## Linux workspace host

The headless Linux host is the first checkpoint for remote workspaces. It runs the same application operation services and state format as the desktop. It owns an explicitly chosen private profile and one owner-only Unix command socket. Client exit or connection loss leaves the host, terminal processes and native provider controllers running. A fresh client reads the host's saved workspace, files and layout and the live PTY state from the same process. Closing the host has the existing shutdown semantics. Linux desktop and headless builds use the same operation dispatch and untrusted CLI admission. Browser and agent-page operations stay with the desktop. The Linux host does not accept trusted-review context from a request body. The desktop connects to one Linux host at a time using its OpenSSH alias and private Unix socket. Overview keeps local and Linux workspaces visible with the SSH alias on remote entries. Selecting a Linux workspace shows the host's active layout, open files, terminals and Codex chats. The desktop reads a current state when the connection starts and on reconnect. Existing terminal sessions reload missed output from the same host process. The desktop identifies a dropped link and reports unconfirmed writes without replay. An unconfirmed chat send retains the draft and blocks another send in that chat. The desktop clears the pending state when the host confirms the submitted draft version. Newer input stays intact, and an unconfirmed draft can be explicitly discarded. Opening a completed remote chat from Overview explicitly acknowledges it in the same host operation. Plain CLI show keeps the completion status. Local browser tabs and user data stay local; HTTP and HTTPS links opened from a remote workspace use the desktop browser. The connection can be recreated from Commands after restarting the desktop. Remote desktop inline review, Codex approvals and active-turn steering use an explicitly paired key. The Linux profile's OpenSSH signers file lists selected public keys in the Cod-review namespace. The desktop proves its local key with a fresh challenge through the verified SSH connection. The host grants the existing private review operations only on that verified connection. Paired ordinary sends and delivery checks share the desktop Codex steering admission. A signer-file change invalidates the grant on the next private operation. The watch stream carries review status and comment counts without draft text, snapshots or submission envelopes. After explicit submission, delivery appears in the originating chat. The host-owner CLI retains its existing approval and review operations, while private draft reads and mutations use the authorized desktop route. Composer and file access remain available after ordinary reconnection. Existing private review comments preserve local edit text and expected versions across reconnect; feeds use the original round, request and native conversation identities to reconcile unconfirmed submission before retry. The private key, authorization proof and signer data do not enter renderer snapshots or the ordinary CLI operation contract. Previews and Save As over SSH require separate validation.

After one explicit Linux host setup, Connect to Linux workspace takes its OpenSSH alias and opens the host's active workspace with all its workspaces available in Overview. From any workspace, open Connect from Commands with the keyboard or pointer. Focus starts in the alias, Enter connects and Escape restores the invoking surface. Connection options reveal a custom socket for a separately managed host and the existing explicit private-review key. A host's saved options are never applied when the alias is edited to another host. The desktop runs the installed host's read-only endpoint command over verified noninteractive OpenSSH. It neither starts nor installs a service by connecting. A missing or unreachable helper reports how to set up the host or check its SSH connection. Failure or cancellation retains the current workspace and the last successful destination. Only the chosen alias and explicit options are remembered. Normal reconnect discovers the endpoint again, and an explicit custom socket stays explicit. The CLI exposes the same first connection and saved reconnect through `codctl workspace connect --alias HOST [--socket-path PATH]` and `codctl workspace reconnect`. It cannot select a private-review key, and a same-host reconnect can retain the user's existing explicit pairing. Connect keeps one active host at a time without creating, renaming or duplicating workspaces. Agterm's documented [remote server](https://agterm.com/docs#remote-server) uses one-time setup and a host-only open action. Cod keeps its shared Overview and existing transport.

Agent workflow preparation uses `codctl workspace prepare --name NAME [--location local|linux] [--folders JSON] [--conversation ID]`. Desktop Settings exposes Default task host in Workspaces. The fresh and reset value is Local. The persisted setting `workspace.defaultHost` applies immediately from any selected workspace. An explicit location overrides it. Linux uses the connected target or its last successfully connected profile via the existing SSH tunnel. Startup does not open an SSH connection. A missing or unreachable Linux host fails the requested operation without creating a local workspace. The saved SSH profile stays on the desktop, outside CLI context and workspace snapshots. Direct preparation on the Linux host socket defaults to Linux and rejects explicit Local. Ordinary workspace creation keeps its local route. The target resolves an exact name in its persisted workspace state on each attempt, rejects ambiguous or closed names, and attaches validated absolute folders together without dropping existing folders. Retrying on the same host after a lost reply resolves the same uniquely named workspace. Desktop preparation opens the resulting confirmed workspace unless subsequent workspace navigation supersedes it. An optional conversation ID moves and follows that existing conversation on the same host. A connected desktop follows a host-side move if it is still viewing the source workspace. Native session, controller, history and cwd are preserved. Ctrl+N still opens a chat in the current workspace. No cross-host conversation transfer is part of this operation.

Move to workspace for a saved local Codex chat also lists folders on the connected paired Linux host. Select the existing workspace and folder with the keyboard or mouse. Confirm the host and full directory before sending the native history. Escape returns to the picker without changing either side. The same action is available as `codctl conversation transfer --id ID --workspace ID --cwd FOLDER` on the desktop. The destination resolves its own attached folder and uses its existing Codex setup. The original native identity, readable thread history, chat name and a supported unsent text draft follow. The resulting chat opens when newer navigation has not superseded the move. Same-host moves retain their existing behavior.

Cod refuses to move an active session or a chat with unresolved approvals, queued input, review, interactive page or running or unknown background work. A Cod-managed native CLI must release the session first. The desktop durably blocks new local writes before publishing the one native session file over the paired SSH channel. Linux publishes a complete file without overwriting an existing native session, validates native resume and saves the destination and its receipt together. It resumes in the selected Linux directory without starting a prompt. A confirmed refusal leaves the original usable. If a reply is lost, the original remains readable without local sending. Reconnect and retry the same move to reconcile the existing receipt or finish the staged import. Restarts do not start another move. After confirmation, Cod closes the source chat and leaves its saved native file in place as a backup. Continue the moved session on Linux.

The first transfer format covers a native Codex session file up to 22 MiB and a text draft up to 1 MiB in the existing SSH command frame. Draft images, skill selections and draft conflicts must be resolved before moving. The transfer omits credentials, provider configuration, repositories, external attachment files, child sessions and live processes. Historical paths stay in history. The compatible native Codex file and protocol were verified between macOS and Linux with invented completed turns. Cod coordinates its own controllers. Independently launched native clients must release the source before moving.

## Local detached agent sessions

Chat settings provide Run new sessions detached, off by default. A change applies when a local provider controller starts. Already running controllers keep their owner. Desktop state, browser tabs, reviews and ordinary terminals stay with the desktop. The daemon owns only the native agent controller, including its active turn, output and approval requests. Desktop-only CLI operations are available while Cod is open.

Closing the main window and Quit use the same confirmation when local agents are active. Leave Running is available if each active local agent was started detached. Stop closes local agent controllers and their subprocess groups. Cancel changes neither work nor window state. The Linux host continues independently of a desktop quit.

A subsequent launch reconnects to the same local controller and native session without submitting another prompt. It combines the persisted output with ordered events from the owner, restores pending approvals, and exposes work completed while disconnected. Owner startup and failed recovery report an error. New detached controllers use an owner from the installed build, including when opening a saved chat. Existing controllers keep their original owner across desktop updates, with the same native identity and event cursor. Each build uses a private local socket and bounded event history, with no network listener. A build-specific owner retires when its last controller is released. Stop on Quit closes the profile's owners, including the original shared owner from before build-specific routing. A machine restart or loss of the owner falls back to the saved native session, with explicit resume. In-flight desktop-owned controllers are never converted while quitting.

## Identity, layout and focus

A fresh profile exposes one Untitled workspace with an empty composer before either the GUI or command socket can observe it. Startup initialization must not race later workspace creation or capture focus after the user opens a command or starts typing. A profile with deliberately closed workspaces remains empty. Transient body focus during dialog teardown must not replace the remembered control, caret or selection.

- A workspace owns folders, conversations, saved material and at most two side-by-side tab groups. Groups hold tabs with stable content IDs. Moving a tab keeps its controller, pin and draft.
- New chat remains available with no open workspaces: create a fresh unnamed workspace and empty composer without restoring closed tasks or starting inference. Reuse a pristine empty composer for this global action.
- New workspaces begin with a chat. Material opens on the left and chats/terminals on the right by default. Explicit tab moves allow mixed groups. Remove nested and vertical splits.
- The title-bar Toggle split view control and Shift+Esc switch between both groups and only the focused group. The first toggle creates a second empty group without starting a provider or shell. Reopening the split restores the saved width and retains the active group and tab. The Files panel keeps its own visibility and width.
- The split control describes visibility. The neutral outline represents a workspace with no split. A collapsed split fills its visible half in neutral gray, and an open split fills both halves equally. The accessible description reports the same layout. The selected tab caption in the active group uses the brighter text tone; the other group's selected caption is muted. Both selected tabs continue into their panels and both panels keep their content brightness. The split control retains its keyboard focus ring and pressed state. [Agterm's title-bar source](https://github.com/umputun/agterm/blob/master/agterm/Views/WindowContentView%2BTitlebar.swift#L144-L177) uses the same visibility convention.
- Explicitly closing the last tab in a visible split group collapses that group and selects the other group's active tab. Keep both group identities and the saved split width. An intentionally opened empty group remains visible until an actual tab is closed. A cancelled close preserves the tab and its split. Reopen closed tab puts a tab back in its original group and reveals both groups when restoring from that close's collapsed side. A group that was already hidden at close follows the ordinary reopen behavior.
- Alt+1 and Alt+2 focus the left and right groups. In single-group view they show only the selected existing group. An absent group is created by opening the split, and an empty group can open its ordinary tab launcher. These actions retain tab order, pins, drafts, browser state and live terminal processes, including through workspace switches. The configurable next and previous pane actions cycle through existing groups, including a parked group, and transfer focus to the selected group's active content. Cycling a one-group workspace has no effect. Closing immediately after a group shortcut follows the requested tab even while the old tab still has keyboard focus. Group arrangement and selection persist across restart. In a single visible pane, switching from a chat to an already loaded native page briefly retains the chat body underneath the incoming browser viewport until the page presents. The outgoing body cannot receive input and clears on another selection, navigation, or if the page cannot present promptly.
- The runtime uses only the one-group or horizontal two-group layout. A saved supported arrangement retains its existing tab identities and width. Conversion of unsupported profiles is outside the application. Explicit left/right focus and visibility bindings remain valid, and pane.zoom bindings use the unified split toggle. Use pane.focusLeft and pane.focusRight in custom keymaps in place of the former numbered one and two command IDs. Vertical split and higher numbered pane commands have been removed. Agterm's [two-pane terminal model](https://agterm.com/docs#terminals) is a behavioral reference. Cod restricts the split to left and right because both sides hold general tabs.
- Every operation accepts an explicit stable target. Commands exposes the same conversation/workspace management actions and guards as context menus, including rename, move, removal and native CLI handoff. The palette retains its original object IDs while open, refreshes action availability on state changes and preserves the query and valid keyboard selection. Agent-origin creation defaults to background. Status updates, slow navigation and streaming must not steal workspace selection, pane focus, caret or scroll.
- A web link or file reference activated in a conversation opens in the group opposite that chat. Reveal the hidden group or create it while preserving the chat's group and the existing tabs. Select and focus the material after a click or keyboard activation unless newer navigation supersedes it. Reuse the existing file or preview tab when already open. A cancelled file chooser changes no layout. A conversation-scoped CLI file or browser open uses the same placement, showing the material there while leaving current focus alone unless explicitly requested. If that destination is already focused, add the tab in the background. Ordinary opens, explicit tab destinations and existing review routing keep their own behavior. Remote HTTP(S) links retain the desktop handoff.
- Explicit navigation may focus its content. Dismissing a picker restores the preceding focus and selection. Streaming follows the end only when the reader was already there.
- Successful CLI requests mean accepted operations, not finished inference. Errors leave state unchanged or expose a recoverable partial outcome; never silently discard drafts.

`conversation.move` relocates the existing conversation and its origin-bound reviews without closing its controller or restarting an active turn. Composer text, images and selected skills follow; unrelated tabs stay put. A pristine destination chat placeholder is removed, while populated drafts remain. The focused conversation follows by default; background transfers preserve unrelated focus unless explicitly requested. Native cwd does not change: returned state and inspection retain the actual directory, and agents must use explicit destination paths or tool cwd. Session-bound context resolves current membership on every call rather than trusting startup workspace environment variables. Review sources retain their original authorized roots across relocation.

Overview separates search, selection and activation. Renaming a workspace or conversation from Commands or a tab menu opens the same targeted inline editor. Escape and keyboard save return to the query. Saving on blur preserves the newer focus target. A conversation name is a Cod display label and leaves native history intact.

### Workspace browser rows and new tabs

Overview browser results retain identity through page-title changes, group moves and restart. They use the browser title and URL as fallback, with Close tab and Reload in the result menu. Closing removes the result. Reopen closed tab restores the browser and its navigation.

The pane's plus button opens a compact shared menu with New file, Browser, Chat and Terminal. New file opens an empty untitled editor in the invoking pane group and focuses it for immediate typing. The draft has no filesystem path until Save As. Merely opening or dismissing the menu creates no tab. Arrows move the menu selection. Enter/Space activates it and Escape cancels, returning useful focus to its invoker. Successful creation focuses the new working surface. Delayed menu dismissal cannot steal that newer focus. Explicit Open file remains available from Files and Commands, and cancelling its picker preserves the source selection. New workspace still starts with chat.

New tab (default Cmd/Ctrl+T) creates fresh content of the selected tab's kind in the targeted pane: a browser starts blank with its address focused; a chat starts empty with the source provider and confirmed effective model/reasoning selection; a terminal starts a new ordinary shell in the source live shell's current directory; a file or file preview starts an empty untitled text buffer. A local HTML page or registered form displayed in the browser creates an ordinary blank browser, never a copy of its response bridge. Review/diff tabs have no meaningful empty review, so they open the four-choice blank tab instead. The same fallback applies to an empty pane or a tab whose type has not been chosen. This action never duplicates a URL, file contents, transcript, attachment, skill selection, permission, native identity, shell command or process. A source with unavailable model or live-directory information must fail explainably rather than silently substitute another model or the terminal's launch directory. An exited terminal uses its recorded directory, subject to the existing fresh-shell rules.

A genuine double-click in unused tab-strip space invokes that same contextual New tab action exactly once. A single click cannot create content. Tabs, their labels and icons, Close/Unpin, Plus and preview controls are excluded from the double-click target; their ordinary actions remain unchanged. Targeting uses the selected content of that group, not an unactivated workspace/tree row. The invocation retains stable workspace/group/source IDs through asynchronous work. A closed or moved source must not reroute creation into another pane. Explicit user creation selects its result; background CLI creation does not steal foreground selection. A later user navigation while creation is pending cancels automatic follow: creation finishes in its original group without replacing the newer current pane or its input.

Every newly created tab appends at the end of its destination group after the existing unpinned tabs. This applies to the chooser, contextual actions, ordinary resource opens, CLI operations and native browser tab requests. The source tab still determines the contextual resource and anchors the destination group. Blank replacements keep their tab identity and position. Existing tabs keep their position when reused, closed tabs reopen at their saved slot, and explicit moves keep their destination indexes.

The existing `pane.new` operation without contextual arguments retains its blank-launcher behavior for CLI compatibility. Its additive `sameAs` source-pane target exposes contextual creation to the CLI. Resource-opening operations use the same stable-source placement rules; contextual CLI creation stays in the background unless `focus=true` is explicit. No separate agent protocol or copy-current-content endpoint is introduced.

The blank fallback offers New file, Browser, Chat and Terminal using shared controls. Tab/arrows and Enter/Space operate its choices. A choice replaces that specific blank tab in place. New file keeps the tab ID, pin, and position and focuses the untitled editor. The same replacement is available through `file new --replace-pane ID`. A closed or changed blank target fails explicitly. Blank tabs survive restart without starting a native process. Contextual chat creation remains local and lazy until the first send; an unstarted source without an explicit model selection uses the same provider defaults without starting a process to discover them. Only provider configuration is inherited, and changing provider clears incompatible inherited configuration. The inherited configuration survives idle native startup and option discovery before the first prompt. Existing native model validation still applies before inference. There is no new default-type preference: existing keymap ownership, validation, live updates and reset control New tab and the separately searchable type-menu action. Window tear-off, duplicate-current-content and creating an empty review/image are intentional omissions.

The unsent Codex composer exposes Model and Effort in the same compact row as the provider, using the existing chat choice controls. The composer selector in [Zed's Agent Panel documentation](https://zed.dev/docs/ai/agent-panel#changing-models) is a secondary reference for placement. A visible unsent Codex draft reads the effective model and effort from the native options on the host and working directory that own the draft. A saved override wins. The draft reuses the result across rendering and pane switches, and the chooser can retry a failed read. Viewing a draft or opening options starts neither a native conversation nor inference and stores no override. Accepting a choice persists the draft's explicit override. Cancelling returns focus without changing it. Changing model offers its supported effort values and clears an incompatible effort override. Untouched controls and the explicit default choice leave the corresponding native defaults in effect. The first send applies the saved options. An inherited Codex selection remains available until changed or the provider is switched. Failed discovery leaves text, attachments and the last saved choice available, with a retry action by reopening the selector.

Reference: [Zed's pinned pane source](https://github.com/zed-industries/zed/blob/482e76524bd33d8cbdfc352f1fef3eefbf2fad92/crates/workspace/src/pane.rs) supplies a Plus popover and dispatches a configured action for a double-click in free tab-strip/drop-target space. Its workspace test verifies dispatch from pinned free space, not creation of a real editor. These are upstream source/test observations, not a live Zed GUI run. Cod's four content kinds and contextual source configuration are deliberate user-directed behavior. Zed's documented source inserts new tabs after the active item by default. Cod appends to the group by user choice. The same upstream source has Save As path selection and dirty-close prompts. Cod instead retains closed unsaved buffers through its recoverable-tab model, preserving fast close/reopen without a destructive discard prompt.

Tab dragging selects an insertion position rather than always appending. Following [Zed's tab drop handling](https://github.com/zed-industries/zed/blob/main/crates/workspace/src/pane.rs), show a narrow insertion marker, keep the dragged tab's identity, and commit one indexed move on drop. The comparison is based on upstream source inspection, not a live Zed GUI run. Dropping on the same slot is a no-op; Escape or dropping outside a Cod tab bar preserves order. Moving across pane groups retains drafts, controller identity and the destination position. Overflowing tab bars scroll while dragging near their edges. Background updates must not replace the drag source or move close targets. The moved tab remains selected; keyboard focus returns to its tab when the drag began there. Existing Move tab left/right and Move to pane actions remain the keyboard alternatives, and order survives restart. Cross-workspace dragging, window tear-off, modifier-drag duplication and drag-to-split are intentionally outside this slice; existing explicit split actions remain available. No drag-specific configuration is introduced.

### Icon control geometry

Regular and compact icon buttons use the shared component and size tokens. Their painted hover, pressed and keyboard-focus area is square; the global text-button minimum height must not stretch a compact icon button. Tab Close and pinned Unpin use the compact variant, with the same geometry for short, long and clipped titles. Tab actions and Overview row actions use a shared translucent hover and pressed fill over the surrounding surface. Interface font changes apply live through the existing shared settings; display scaling changes physical pixels without changing the square shape. Disabled icons retain their geometry, do not brighten on hover and cannot activate. Tab-bar New tab and the title-bar split control use the regular variant. Tab Delete / Close tab keeps its current behavior; Enter/Space on a focused icon button performs that button's action, without activating its surrounding tab. No new preference, rename flow, dialog or persistence state is introduced by this geometry repair.

Delayed pane selection remains keyboard usable. The focused group can be shown alone and positional focus commands can switch groups; once its state and DOM are delivered, the selected chat receives actual composer focus and immediate typing extends its existing draft. Focus completion must follow rendered state, not an assumed animation-frame count or the operation reply alone. A newer explicit navigation, modal, closure or workspace change cancels an obsolete completion, and no old native notification may restore a hidden side. Mouse activation and Focus files / return retain the same target and cancellation rules. Chat and terminal navigation use Overview, tabs and positional pane actions. New terminal is an explicit creation action. Delayed menu close cleanup restores its origin only while focus still belongs to that menu or the page body; it must preserve a newer composer, file or navigation focus. Command palette cancellation restores the invoker and its selection synchronously with Escape. Its later close cleanup must also preserve new typing and caret movement in that same invoker; it cannot replay the old selection after newer input. Native-page and Markdown-frame invokers retain their existing focus-return path. These ephemeral events are never persisted or replayed after restart.

### Manual Developer Tools

F12 and Commands > Toggle Developer Tools toggle the inspector for the invocation's focused surface. Chat, files, navigation and browser chrome belong to the Cod renderer; native website and registered-page content use their own WebContents. Commands retains the native origin when opened from a page, even though the palette itself belongs to Cod. A vanished target fails rather than falling back to another page or the app. Inspection never changes workspace, tab selection, resource identity or drafts.

The alternate shortcut follows [Electron's native menu source](https://github.com/electron/electron/blob/main/lib/browser/api/menu-item-roles.ts): Command+Option+I on macOS and Ctrl+Shift+I on Linux. Bindings come from the shared registry; keymap overrides are validated, apply live, survive restart and reset to these defaults. Bare function keys are allowed in explicit keymap configuration without admitting unmodified text keys. Terminal editing authority is preserved for remapped control-letter shortcuts. Electron's internal inspector window does not deliver `before-input-event` ([upstream limitation](https://github.com/electron/electron/issues/28770)); it uses native Close, while toggle shortcuts act from the inspected surface. Cod intentionally does not add a custom inspector window or global keyboard hook to override this. This comparison is based on source and [Electron WebContents documentation](https://www.electronjs.org/docs/latest/api/web-contents), not an observed Zed GUI.

Inspectors open as ordinary detached Electron DevTools windows, identify their inspected page and can be closed through their native controls or the toggle shortcut from the inspected surface without closing the page. Ordinary browser context menus expose Inspect element at the clicked coordinates; registered pages with their restricted response bridge intentionally omit that action. Escape/cancel retains the context-menu origin. Existing rename and selection behavior is unchanged. Closing the owner destroys its inspector; reopening a tab or restarting Cod does not automatically open tools. No inspector-open preference is persisted, no runtime agent CLI capability or debugging port is added, and renderer/browser sandbox and bridge isolation remain intact.

## Persistence and lifecycle

Persist layout, resource IDs, open views, composer text/images/provider/selected skills, native-session references, file drafts, review drafts and close/reopen history. Restore records without replaying commands, inference or arbitrary website form submissions.

Live replies and routine tool progress reach the renderer as they arrive. The first unsaved passive conversation update requests one shared checkpoint after two seconds. An ordinary durable operation or a turn-completion checkpoint can save that progress sooner in the same atomic state replacement. A normal quit saves the latest progress and drafts before closing. Completion, interruption, permissions and explicitly durable operations keep their existing checkpoints.

Composer typing persists the latest text without echoing the application snapshot back to its originating UI. Consecutive trusted text edits may share a durable save within a 150 ms batch; intervening operations form ordering barriers, so a delayed save cannot restore a sent or cleared draft. Save acknowledgment still follows durable persistence, and failures reject all callers in the batch. Text-only edits atomically save a small `composer-text.json` overlay without cloning or serializing histories and attachments. Full state checkpoints include the latest drafts and advance an internal checkpoint token; startup applies an overlay only to its matching checkpoint, so stale text cannot resurrect a sent or cleared draft. Corrupt matching draft storage prevents silent recovery with lost text. Text-only `conversation.composer` updates preserve existing images when `images` is omitted; an explicit empty array removes them. Attachment changes and CLI composer updates still notify the UI.

Image previews close with Escape or their close control and return focus to the invoking thumbnail immediately. A delayed close event must preserve a newer keyboard or pointer target, including attachment removal. Pasted images insert stable `[Image N]` references at the current selection. Attachment removal removes its insertion marker without renumbering other images; thumbnail captions and provider content identify the same image. References and image data persist with composer drafts. Sending waits for attachment reading to finish. An image-only first message retains its attachment through draft restart, reaches exactly one native provider prompt and remains visible after conversation restart. A newly initialized native session can be ready before that first send is admitted; readiness alone does not establish message delivery.

Composer ownership follows the conversation identity, not a reusable pane. After a failed create or resume, opening another conversation in the same pane must bind typing, attachment and send actions to the new conversation. Its unsent text and images must survive switching chats and restarting the app.

Streaming updates may be batched for display; user actions still publish immediately. Streaming updates retain rendered Markdown for unchanged visible messages, including when the current answer moves out of the activity row. Collapsed tool rows retain their summaries without constructing full output blocks until expanded, and closing a row releases its rendered output. Background streaming must not require renderer copies or full JSON comparisons of all conversations merely to detect a focus change.

Browser restoration loads an ordinary page only when its actual visible viewport is laid out or navigation is explicitly requested. Inspecting records and changing unrelated state do not wake dormant pages. Already loaded views remain alive across workspace switches, preserving forms and media. Failed-page diagnostics may create a passive error view without retrying its URL. Native view destruction during application shutdown must preserve saved tab records, including when shutdown begins while a close decision is pending.

Browser tab close honors the page's native beforeunload prevention before removing its pane or adding reopen history. Stay is the default and preserves the existing page and form; only Leave discards it. CLI closure uses the same behavior. Workspace close asks guarded pages before stopping agents or shells. If a later page cancels, earlier explicitly discarded tabs remain individually reopenable and the workspace stays open; no cancelled tab is archived as closed. This protection applies to tab/workspace operations, not forced process termination.

Closing and immediately reopening a tab leaves the restored tab selected and ready for typing. A late physical-focus completion from the close cannot issue another selection and switch back to its fallback tab. Closing a chat tab removes the view, not its conversation or active turn. Closing a terminal stops its owned shell; reopening requires an explicit fresh-shell action. Closing a busy workspace identifies the work that will stop and defaults to Cancel; CLI callers must explicitly request forced closure. Failed stop or mutation retains usable context. Externally owned CLI sessions are not silently seized or killed.

Reopening a selected closed workspace uses its stable ID. A missing target reports that the workspace is no longer closed. A selected workspace with terminal panes still requires confirmation before starting fresh shells. The existing workspace reopen operation restores the saved layout, tabs and history.

CLI send and desktop providers without steering durably append messages to the conversation's FIFO queue during an active turn. Text, image references/data and exact skill references stay together. The same queue operations serve UI and CLI. Waiting entries appear above the composer and can be cancelled or edited in place without replacing the next draft; an entry being edited blocks dispatch until saved or cancelled. Successful native completion starts the next entry without stealing focus. Interruption, provider failure and application restart pause the queue until explicit continuation. A persisted in-flight entry becomes uncertain after restart and must never be resent automatically; show its uncertainty and allow dismissing it after native-history inspection. ## Pinned tabs

Pinning protects any tab kind, including chats, browsers and an unfilled New tab, from routine closure. Pin state belongs to the stable tab identity, not its title, resource type or numeric position. Each pane places pinned tabs first, retaining order inside the pinned and ordinary segments. Keyboard tab navigation and native-page Commands target the same exact tab as mouse actions. Escape cancels menus and returns focus. The ordinary Close tab command/shortcut, tab Delete and middle-click never close a pinned tab. CLI operations share these protections; explicit inclusion of a pin is opt-in, not inferred from a resource ID. ## Acceptance boundaries

Navigation responsiveness is measured from the actual keyboard or mouse action to its first visible result and settled frame, separately from native page navigation and paint. Compare an empty profile with representative saved histories, attachments, multiple workspaces and already loaded native pages, both idle and while another conversation streams. Account separately for renderer work, IPC and operation queueing, persistence, state snapshots and native creation/layout/focus. A navigation action must not perform unnecessary work on unrelated history, lose draft text or weaken durable close/reopen and restart behavior. Correctness and responsiveness evidence are separate; a final selected tab does not establish that switching was fast. No animation, framework replacement or new preference is implied by this repair. JSON-line readers inspect each incoming chunk once and join a completed frame once, retaining their existing size, timeout and UTF-8 limits. Provider diagnostics that do not change application state must not trigger state broadcasts or disk writes. Renderer snapshots include complete transcripts only for the visible chat tabs; hidden chats retain their label, queue and attention metadata without copying historical tool output or image bytes. The CLI and durable history remain complete, and switching a chat into view supplies its current transcript. Rollback backups do not clone live provider fields that rollback already preserves. Native browser metadata changes share the existing short snapshot batch, while initial tab creation remains visible independently of page loading.

Long conversations initially render a recent text-bounded window rather than synchronously formatting every historical message. Scrolling to its beginning loads an earlier window without moving the current content; an Earlier messages action also provides keyboard access. Current-content search includes all loaded history, and full-history search can still require substantial rendering for a very large conversation. Navigation and new messages retain the composer text, selection, attachments and the latest answer; loading older content never truncates persisted or CLI history. This repair introduces no additional storage format or transport protocol. When Codex resumes with a partial snapshot, keep previously displayed messages and tools in order and merge overlapping native items once. When no cached rows remain to reveal, Earlier messages can fetch one bounded page using the native item cursor. A failed read keeps the current transcript and can be retried. The cursor ends when the provider reports there is no earlier page.

Selecting an existing workspace, tab or pane and changing split visibility can render before the state checkpoint finishes. Requests still complete after the checkpoint, later mutations retain their order, and a failed save restores and republishes the previous selection. The saved layout and restart behavior stay the same.

Exercise complete journeys with real Electron, temporary files, real Git and real PTYs: create/switch tasks, discuss/edit/review a spec, implement across two repositories, interrupt work, return later, close/reopen and restart. Include mouse and keyboard paths, native embedded-view shortcuts, concurrent changes, failures and recovery. Inspect screenshots at normal and wide window sizes; passing assertions alone does not establish coherent design.

Scripted provider subprocesses verify deterministic protocol and UI behavior. Separately verify live identity/history round trips, permissions, interruption, images and plugin execution for each supported provider. Credential or platform gaps are BLOCKED, not inferred passes.

Official-extension checks must exercise login/unlock, generation, saving, actual content-script autofill and restart against an invented vault. Ad-blocking fixtures verify network/cosmetic integration and host exceptions; representative public-site comparisons are needed to claim AdGuard-comparable effectiveness. Keep real account data, screenshots, logs and per-run evidence in ignored local artifacts.

Diff reviews render the saved unified diff in hunk order: context appears once with both line numbers, additions and removals retain their own side, and missing-final-newline markers remain visible. Existing snapshots use their saved diff text and manifest without migration. Comment selections must stay within one file, hunk and side; context supports either side so old-side anchors remain valid. Each file has one repository-relative heading, with both paths shown only for an actual rename or copy. Comparison labels use the supplied refs and shorten literal commit hashes. Full paths and resolved revisions remain available in descriptions. Long path prefixes and refs ellipsize in narrow panes without altering line scrolling or anchor coordinates.
