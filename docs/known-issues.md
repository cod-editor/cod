# Known user-experience defects

Open defects identified in the user-experience review of 2026-11-15. UX-01, UX-02, UX-03, UX-04, UX-05, UX-06, UX-07, UX-08, UX-09, UX-10, UX-11, UX-12, UX-17, UX-18, UX-19 and UX-20 are implemented and passed focused real-Electron acceptance tests (including draft restart checks); they are awaiting publication through the full CI baseline. All other items below remain open. UX-06 focused checks verify dormant pages make no requests until shown and retain their loaded forms; sustained memory impact has not been measured. UX-07 checks cover managed new tabs, sandboxing, opener messaging, POST navigation, self-close, parent closure, restart and background workspace focus in isolated Linux Electron; live-site/macOS compatibility remains unverified. UX-08 checks cover Back/Forward after reopen and restart, passive failed-page recovery and absence of POST resubmission; navigation stores bounded URL/title entries without form state. UX-18 also covers preserving saved tabs when extension removal callbacks run during shutdown. This is a repair backlog, not a statement that every other workflow is verified. Browser findings were reproduced in isolated Linux Electron; component findings used production UI modules in headless Chromium with invented data and mocked application operations. Reference-product comparisons used official documentation. macOS GUI, live accounts and sustained memory growth were not verified.

## Repair and verification order

1. New user reports, including UX-19 and UX-20, precede older pending repairs. UX-16 remains pending native macOS evidence. UX-18 and UX-17 take precedence once the current coherent fix reaches its verification boundary.
2. UX-01 through UX-03: prevent silent loss and stale documents.
3. UX-04 and UX-05: make review changes and pending work intelligible.
4. UX-06 through UX-08: make browser startup, tabs and return navigation predictable.
5. UX-09 through UX-15: unify focus, action discovery, settings and diagnostic attribution.

For each repair, test the complete task with keyboard and mouse, interruption, workspace switching and restart where applicable. Use representative histories and attachments for performance checks. Mark an item resolved only after recording the concrete acceptance result in its change/PR; selected passing tests do not replace a passing full CI baseline.

Detailed local probes and screenshots live under ignored `artifacts/ux-audit/`, `artifacts/ux-chat-review/`, `artifacts/ux-navigation-audit/` and `artifacts/ux-browser-audit/`. They are supporting evidence, not required repository inputs.
